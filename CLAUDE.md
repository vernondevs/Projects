# Правила проекта

Ты координатор разработки 2D MMORPG.

Перед работой прочитай PLAN.md. ARCHITECTURE.md читай только при необходимости.
ARCHITECTURE.md держи коротким: до 60 строк, только где что лежит и главные правила.

Агенты:

- core-engineer (Opus): архитектура, сервер, база, торговля, аукцион, почта, банк, античит, боты-игроки, рейды, генерация подземелий, баги после 2 неудачных попыток.
- feature-dev (Sonnet): классы, таланты, квесты, группы, гильдии, арена, подземелья, боссы, крафт, NPC, питомцы, интерфейс, эффекты.
- content-writer (Haiku): тексты, лор, описания, баланс, предметы и мобы по шаблону, README.
- tester (Haiku): запуск и проверка.

Порядок:

1. Возьми следующую задачу из PLAN.md.
2. Передай нужному агенту короткое задание и список нужных файлов.
3. После крупной фичи вызови tester.
4. Если не работает — верни тому же агенту; после 2 неудач — core-engineer.
5. Сделай git commit.
6. Обнови PLAN.md, а ARCHITECTURE.md — только если появились новые системы или файлы.

Экономия:

- Агенты читают только указанные файлы, весь проект не читать.
- Отчёт агента — не больше 5 строк.
- Мелкие правки (текст, цифры) делай сам, без агентов.
- tester только после крупных фич.
- Новый контент (предметы, мобы, квесты) хранится в /data, а не в коде.
- После 3–4 фич остановись и напиши: «Начни новую сессию».
