# Пепельный Предел

Браузерная 2D MMORPG с видом сверху. Клиент на Phaser 3, авторитарный сервер на Node.js и Colyseus, прогресс игроков хранится в SQLite. Вся графика — оригинальный пиксель-арт 32×32, его рисует генератор в `tools/gen`.

## Что есть в игре

- **Мир 180×140 тайлов.** Город Эмберхолл (безопасная зона, торговка, фонтан возрождения), Зелёные холмы (ур. 1–8), Шепчущий лес (8–15), Гнилые топи (15–22), Пепельная пустошь (22–26) и данж Пепельные чертоги (26–30).
- **Мультиплеер в реальном времени.** Игроки видят друг друга, есть общий чат. Сервер проверяет каждое действие: скорость, дистанцию, перезарядку, ману, инвентарь и цены.
- **Три класса.** У воина, мага и лучника своя автоатака, по 4 активных умения с перезарядкой и по 3 пассивки.
- **Прокачка.** Опыт, уровни до 30, по 3 очка характеристик за уровень (сила, ловкость, интеллект, выносливость), по 1 очку умений за уровень. Дерево умений с требованиями по уровню и по предыдущим умениям.
- **Лут.** Личные мешки с добычей. Предметы бывают обычными, редкими и эпическими, со случайными свойствами. Инвентарь на 24 ячейки, 6 слотов экипировки, зелья, торговец.
- **Три босса с фазами** и атаками, которые заранее показывают зону удара:
  - **Древний Энт** (лес, ур. 14): корни под ногами, удар конусом. Во 2-й фазе призывает саженцев и поднимает бурю листьев вокруг себя.
  - **Болотная Ведьма** (топи, ур. 22): ядовитые лужи. Во 2-й фазе телепортируется с ядовитой новой и призывает утопленников, в 3-й впадает в ярость.
  - **Повелитель Пепла** (данж, ур. 30): огненное дыхание и сокрушение. Во 2-й фазе обрушивает метеоритный дождь, в 3-й — кольцо пламени, от которого спасает только место рядом с ним, и призывает бесов.

  У каждого босса 4 уникальных предмета. Каждый участник боя получает свой мешок, и уникальный предмет в нём подходит его классу.
- **Графика.** Анимации ходьбы, атаки и смерти в четырёх направлениях, эффекты умений, частицы, всплывающие цифры урона. Анимированная вода, огни и темнота в данже, атмосферные частицы в каждой зоне, мини-карта.
- **PvP-арена** 1×1 и 2×2 с рейтингом Elo, рангами, сезонами и таблицей лидеров (подробно — в разделе «Арена»).

## Установка и запуск

Нужен **Node.js 22.13 или новее**: используется встроенный модуль `node:sqlite`, поэтому собирать нативные зависимости не нужно.

```bash
npm install
npm run dev
```

`npm run dev` одной командой генерирует ассеты и запускает сервер (порт 2567) и клиент (порт 5190). Откройте http://localhost:5190, введите имя и пароль. Персонаж создаётся при первом входе, а при следующих входах пароль проверяется.

Чтобы проверить мультиплеер, откройте вторую вкладку и войдите другим героем.

Режим production, когда сервер сам раздаёт собранный клиент:

```bash
npm start            # сборка клиента в dist/ и запуск сервера
# откройте http://localhost:2567
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `2567` | порт HTTP и WebSocket сервера |
| `DB_PATH` | `server/data/game.sqlite` | файл базы SQLite |
| `VITE_SERVER_URL` | `ws://<хост>:2567` в dev, тот же адрес в production | адрес сервера для клиента |

## Управление

| Действие | Клавиши |
|---|---|
| Идти | WASD или стрелки; клик по земле (путь вокруг препятствий ищется сам) |
| Атаковать | клик по врагу (герой подойдёт и начнёт автоатаку); Tab — следующая цель рядом |
| Умения | 1–4. Умения по площади бьют в сторону курсора или по цели |
| Зелья | Q — здоровье, E — мана |
| Подобрать добычу | клик по мешку или Пробел рядом |
| Торговец | клик по торговке Марфе в городе или F рядом |
| Окна | C — герой и характеристики, I — сумка и экипировка, K — дерево умений, P — арена, Esc — закрыть |
| Чат | Enter — написать, Enter — отправить |

Перетаскиванием можно переложить вещи в сумке. Когда открыт торговец, клик по вещи в сумке продаёт её.

## Арена

PvP-бои в режимах **1×1** и **2×2**. Вся логика подбора, матча и рейтинга работает на сервере, клиент только показывает результат.

### Как попасть на арену

1. Откройте окно арены: подойдите к **Распорядителю арены** у городской площади (клик по нему или F рядом), либо нажмите **P**, либо кнопку «Арена» под мини-картой.
2. Нажмите «В очередь» в нужном режиме.
   - **1×1** — только в одиночку.
   - **2×2** — либо с напарником по группе, либо одному: тогда сервер сам соберёт пару из одиночек с близким рейтингом. Группа собирается в том же окне: впишите имя игрока и нажмите «Пригласить». Напарник должен быть в мире и принять приглашение.
3. Когда соперники найдены, у всех участников появляется окно «Матч найден». На ответ даётся **15 секунд**.
   - Отказ или молчание убирают игрока из очереди. Если отказался один из группы, очередь покидает вся группа.
   - Остальные возвращаются в очередь и сохраняют накопленное время ожидания.

### Подбор соперников

- Сначала ищутся соперники с рейтингом **±100**. Каждые 10 секунд ожидания окно расширяется на 50, но не больше чем до ±1000. В окне арены видно время ожидания и текущее окно.
- В 2×2 сравнивается **средний рейтинг команд**.
- **Против накрутки:** одних и тех же соперников нельзя получить больше **3 раз подряд**. После трёх матчей подряд против одного игрока сервер ищет других. В окне очереди при этом появляется подсказка.

### Матч

- Каждый матч — отдельный инстанс: своя комната Colyseus (`ArenaRoom`) на небольшой каменной карте 34×24 с колоннами и стенками для укрытий. Стены перекрывают снаряды.
- Перед боем идёт **обратный отсчёт 5 секунд**: двигаться и бить нельзя, HP, мана и перезарядки полностью восстанавливаются.
- Бой использует обычные атаки и умения классов. Зелья на арене не работают: у всех одинаковые условия. Площадные умения и цели работают против вражеских игроков. Союзник подсвечен зелёным, враг красным, Tab выбирает следующего врага.
- **Победа** — когда все противники повержены.
- **Лимит 3 минуты.** После него побеждает команда с бо́льшим суммарным процентом HP. При равенстве — ничья.
- **Выход или обрыв связи** до конца матча засчитывается этому игроку как поражение. Если не пришёл или вышел весь состав команды, побеждает соперник.
- После боя показывается экран результатов: победа или поражение, изменение рейтинга, урон, исцеление (вампиризм), убийства и смерти каждого игрока. Кнопка «Вернуться в мир» (или автоматически через 20 секунд) переносит героя туда, где он стоял перед матчем.
- Пока герой на арене, войти им в мир с другой вкладки нельзя.

### Рейтинг, ранги и сезоны

- **Elo:** старт 1000, коэффициент K = 32. Рейтинги 1×1 и 2×2 отдельные. В 2×2 изменение считается по среднему рейтингу команд.
- **Ранги:** Бронза (до 1099), Серебро (1100+), Золото (1300+), Платина (1500+), Алмаз (1700+).
- **Сезон длится 4 недели.** В конце сезона каждый, кто сыграл хотя бы один матч, получает награду своего ранга, отдельно за каждый режим:
  - **титул** над именем, например «Золотой гладиатор»;
  - **рамку** цвета ранга вокруг имени и панели героя;
  - **уникальный медальон арены** — от бронзового до алмазного.

  Затем рейтинг частично сбрасывается: сдвигается к 1000 на половину расстояния (1400 → 1200, 800 → 900). Кто в мире, получает награду сразу, остальные — при следующем входе. Если в сумке нет места, медальон дождётся, пока оно появится. Активный титул выбирается в окне арены.
- **Окно арены** показывает текущий рейтинг, ранг, место и счёт побед и поражений, кнопки очереди и время ожидания. На вкладке «Лидеры» — топ-100 каждого режима, на вкладке «История» — последние 20 матчей. Топ доступен и по HTTP: `GET /api/arena/top/1v1`, `GET /api/arena/top/2v2`.

### Где хранятся данные

Всё в той же базе `server/data/game.sqlite`:

| Таблица | Что в ней |
|---|---|
| `arena_seasons` | сезоны: начало, конец, закрыт ли |
| `arena_ratings` | рейтинг, победы, поражения и ничьи по сезону, режиму и игроку |
| `arena_matches` | матчи: режим, сезон, длительность, победитель, причина конца |
| `arena_match_players` | участники матча: команда, итог, рейтинг до и после, урон, исцеление, убийства, выход из боя. Отсюда берутся история и проверка повторов |
| `arena_rewards` | сезонные награды и отметка о выдаче |

Титулы и рамка хранятся в прогрессе героя (столбец `data` таблицы `players`).

### Код

```
shared/arena.ts             режимы, ранги, Elo, константы подбора и сезона, карта арены, типы сообщений
server/src/arena/queue.ts   очередь, сбор команд 2×2, окно рейтинга, подтверждение, запрет повторов
server/src/arena/party.ts   группы на двоих
server/src/arena/store.ts   таблицы арены в SQLite, сезоны, история, награды
server/src/arena/rewards.ts выдача титула, рамки и медальона
server/src/rooms/ArenaRoom.ts  инстанс матча: отсчёт, бой, итог, Elo, возврат в мир
client/src/ui/arena.ts      окно арены, подтверждение, табло боя, результаты, рамка группы
```

Чтобы поменять правила, правьте константы в `shared/arena.ts`: длительность боя, отсчёт, окно подбора, пороги рангов, длину сезона, долю сброса и лимит повторов. Сервер и клиент берут их оттуда.

## Торговля

- Правый клик по игроку → «Предложить обмен». У второго 30 секунд, чтобы принять или отклонить. Игроки должны стоять рядом (до 5 тайлов), не в бою и не на арене. Кнопка «Обмен» у мини-карты отключает входящие запросы.
- В окне «Вы отдаёте» / «Вы получаете» по 8 слотов и поле золота. Предметы перетаскиваются из сумки (или клик по ним). Можно дарить: получатель видит пометку «Подарок».
- Защита: оба жмут «Готов», затем оба «Обменять» (кнопка активна через 3 секунды после последнего изменения). Любое изменение сбрасывает подтверждения и подсвечивает слоты.
- Предметы «Привязан к персонажу» (уникальные вещи боссов, награды арены) передать нельзя. Если в сумке нет места — обмен не проходит с понятной ошибкой.
- Обмен отменяется, если кто-то отошёл, закрыл окно, вступил в бой или отключился. Вся логика на сервере (`server/src/trade/`), перенос — одной транзакцией SQLite, журнал — таблица `trade_log`. Предмет в окне обмена нельзя использовать, продать или надеть.

## Админ-панель

Права никому не выдаются автоматически. Выдать или снять (герой должен существовать; действует со следующего входа):

```
npm run db -- admin Имя on
npm run db -- admin Имя off
```

Админам в меню появляется кнопка 🛠 (клавиша F10): вкладки «Игроки» (кик/бан/разбан/ТП/выдача), «Выдача» (предмет, золото, опыт, уровень), «Мир» (призыв моба или босса, объявление, телепорт), «Логи» (сделки и журнал админов). Все команды `admin:*` проверяются сервером по флагу в БД; попытки без прав игнорируются и пишутся в журнал (`admin_log`). Баны: колонки `banned_until`/`ban_reason`. Призванные мобы не возрождаются.

## Структура

```
shared/          общий код клиента и сервера: карта, формулы, классы, умения, предметы, мобы, протокол, поиск пути
server/src/      сервер Colyseus: комната мира, Schema, бой, ИИ мобов, боссы, награды, инвентарь, SQLite
client/src/      Phaser-сцены, отрисовка мира и юнитов, эффекты, интерфейс на DOM
client/public/assets/   сгенерированные PNG и manifest.json
tools/gen/       генератор пиксель-арта: тайлы, юниты, объекты, иконки, эффекты
tests/           боты для проверки сервера и скриншоты клиента через Chrome
```

Сервер авторитарен. Клиент шлёт только намерения: направление, точку, цель, умение. Публичное состояние (позиции, здоровье, анимации) синхронизируется через Colyseus Schema. Личное (инвентарь, опыт, характеристики) сервер отправляет только владельцу. Карта детерминированно генерируется из общего seed одинаково на клиенте и сервере, поэтому по сети не передаётся.

## Как добавить нового моба

1. **Описание.** Добавьте запись в `shared/mobs.ts`:

   ```ts
   bat: { id: "bat", name: "Летучая мышь", sprite: "bat", size: 1, hp: 0.7, dmg: 0.9, armor: 0.5, xp: 0.9,
          speed: 120, aggro: 180, range: 34, attackCd: 1.1, radius: 9, color: "#5a4a6a" },
   ```

   Здоровье, урон, броня и опыт заданы множителями к базовой кривой по уровню (`mobStats` в `shared/formulas.ts`). Для дальнего боя укажите `projectile` (`"fire"`, `"poison"`, `"shadow"`).
2. **Спрайт.** Есть два варианта.
   - Нарисуйте свой лист и положите его в `client/public/assets/units/bat.png`. Раскладка такая: кадр 32×32 (у боссов 64×64), 12 столбцов (0–3 ходьба, 4–7 атака, 8–11 смерть) и 3 строки (вниз, вверх, вбок вправо; влево — отражение).
   - Либо опишите моба в генераторе `tools/gen/units.ts` (`UNIT_ART`): для гуманоидов достаточно спецификации `HSpec`.

   Затем запустите `npm run assets`: манифест соберётся сам, ручные PNG тоже попадут в него.
3. **Место обитания.** Впишите id моба в список `mobs` нужной зоны в `ZONES` (`shared/map.ts`). Точки появления и уровни распределятся автоматически.

**Новый босс** добавляется так же, плюс:
- `boss: true`, фиксированный `level`, `respawn` и список `uniques` в `shared/mobs.ts`;
- точка появления в `BOSS_SPAWNS` (`shared/map.ts`);
- класс со способностями в `server/src/game/bosses.ts`. Наследуйтесь от `Boss`, задайте `thresholds` для фаз и способности через `this.ability(...)`; для зон удара с предупреждением используйте `world.telegraph(...)`.

## Как добавить предмет

- **Новый базовый тип** — запись в `BASE_ITEMS` (`shared/items.ts`). Нужны слот, иконка, необязательное ограничение по классам и функция `roll(ilvl)` с основными характеристиками. Тип сразу начнёт выпадать с мобов, а редкость и случайные свойства добавятся сами.
- **Иконка 32×32.** Положите PNG в `client/public/assets/icons/<имя>.png` или нарисуйте её в `tools/gen/objects.ts` (`itemIcon` и список `ITEM_ICONS`).
- **Уникальный предмет босса** — запись в `UNIQUES` (`shared/items.ts`) с именем, базой, уровнем, свойствами и описанием. Затем добавьте его id в `uniques` нужного босса.

## Проверки

```bash
npm run typecheck    # TypeScript для всего проекта
npm test             # 27 проверок мира (вход, бой, прокачка, лут, боссы...) и 14 проверок арены
npm run test:arena   # только арена: 1×1, 2×2 с группой, подтверждение и отказ, Elo, история, лидеры,
                     # запрет повторов, выход из боя, победа по времени, конец сезона и награды
npm run screenshot   # скриншоты клиента в tools/out/ (сценарии: basic, ui, tp:<моб>, boss:<ent|witch|ashlord>)
npm run screenshot:arena  # арена в 4 браузерных клиентах через интерфейс: очередь, подтверждение, бой 1×1 и 2×2, результаты
npm run db           # таблица героев из базы (npm run db -- <имя> — подробно)
```

Тест арены запускает сервер с укороченным боем (`ARENA_MATCH_MS=9000`), чтобы проверить победу по времени.

Тесты поднимают отдельный сервер на порту 2601 с временной базой и включают отладочные команды (`TEST_MODE=1`). В обычном запуске отладочные команды отключены. Скриншотам нужен установленный Chrome или Edge; путь можно задать в `CHROME_PATH`.

Полезные отладочные утилиты: `npx tsx tools/preview-map.ts` (схема всей карты) и `npx tsx tools/preview-region.ts x y w h` (участок карты тайлами). Результат появляется в `tools/out/`.
